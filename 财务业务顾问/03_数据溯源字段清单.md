## 0. 溯源目标

满足成功标准「**100% 流水可回溯到源**」：

- 任意一笔**金蝶凭证** → 一路回查「原始银行流水 → 采集批次 → 复核人/复核时间 → 推送记录 → 凭证号」；
- 反之，任意一笔**原始流水** → 查它最终生成的**凭证号**；
- 杜绝「账对不上、查无实据」。溯源字段随业务流转**只追加、可验证、防篡改**。

---

## 1. 溯源链路

| 溯源方向 | 链路 | 关键字段 |
|-|-|-|
| 账 → 单 | `biz_push_record.voucher_no` → `dwd_trans_flow.record_id` → `ods_bank_raw_flow.raw_id` | voucher_no、record_id、raw_id |
| 单 → 账 | `dwd_trans_flow.record_id` → `biz_push_record.voucher_no` | record_id、voucher_no（**双向绑定，强制非空**） |
| 批量召回 | `dwd_flow_batch.batch_no` → 本批全部 `dwd_trans_flow` + `ods_bank_raw_flow` | batch_no / batch_id |
| 操作追溯 | `aud_audit_log`（谁、何时、做了什么） | actor / action / created_at |

## 2. 溯源字段清单（按对象）

### 2.1 采集批次（批次号 = 溯源入口）

| 字段 | 说明 |
|-|-|
| `batch_no` / `batch_id` | 每次采集生成的唯一批号（人类可读，如 `B20260824-0001`） |
| `source_type` | 数据源类型 MOCK / FILE / API |
| `bank_id` / `account_id` | 来源银行 / 账户 |
| `source_ref` | 来源引用（文件路径 / 接口标识 / 文件名） |
| `contract_version` | 契约版本（v1） |
| `flow_date_start` / `flow_date_end` | 本批流水日期范围 |
| `total_count` / `total_amount` | 采集上报（预期）总笔数 / 总金额（对账钩稽基准） |
| `imported_by` / `imported_at` | 导入人 / 导入时间 |

### 2.2 流水主表（记录级 ID = 逐条定位）

| 字段 | 说明 |
|-|-|
| `record_id` | 记录级唯一 ID（逐条定位） |
| `dedup_key` | 幂等去重键（`SHA256(bank_id|account_id|txn_no|txn_date|amount|dc_flag)`） |
| `batch_id` | 回链批次 |
| `bank_id` / `account_id` | 回链来源银行 / 账户 |
| `raw_id` | 回链原始归档（结构化 → 原始反向溯源） |
| 契约字段 | `txn_no/txn_date/txn_time/currency/amount/dc_flag/counterparty_name/counterparty_account/summary` |
| `process_status` | 业务阶段 `LOADED→VALIDATING→REVIEW_READY→REVIEW_PASSED→PUSHED→KINGDEE_POSTED`（异常 `REJECTED`） |
| `validation_status` | 校验结论 PENDING/PASS/WARN/FAIL |
| `ext_json` | 预留扩展（不改写主表） |

### 2.3 原始归档（ODS）

| 字段 | 说明 |
|-|-|
| `raw_id` / `raw_content` | 原始流水原样归档（JSON，含非必需字段） |
| `raw_hash` | `raw_content` 的 SHA256（幂等 + 防篡改） |
| `source_file_name` / `source_uri` | 来源文件 / URI |

### 2.4 校验留痕（逐规则审计）

| 字段 | 说明 |
|-|-|
| `validation_id` | 校验记录主键（一条流水一条规则各一行） |
| `record_id` / `batch_id` | 回链 |
| `rule_code` | 命中规则（R001–R005 等） |
| `rule_result` | PASS / FAIL / WARN |
| `error_detail` | 缺哪些字段 / 重复对哪个键 / 阈值多少 |

### 2.5 复核留痕

| 字段 | 说明 |
|-|-|
| `review_id` | 复核记录主键（同一流水可多次复审，保留历史） |
| `review_result` | PASS / REJECT / ADJUST |
| `reviewer` / `review_time` | **复核人 / 复核时间** |
| `matched_subject` | 人工指定科目（低置信流水由财务填入） |
| `comment` | 复核备注 |

### 2.6 推送与凭证关联（双向绑定核心）

| 字段 | 说明 |
|-|-|
| `push_id` / `push_status` | 推送记录 / 状态（PENDING/SUCCESS/FAILED） |
| `voucher_no` | **金蝶凭证号**（账→单、单→账 双向绑定） |
| `kingdee_doc_no` | 金蝶单据号 |
| `pushed_by` / `pushed_at` | 推送人 / 推送时间 |
| `retry_count` / `error_msg` | 重试次数 / 失败原因 |
| `response_payload` | 金蝶响应原文留痕 |

### 2.7 审计日志（防篡改）

| 字段 | 说明 |
|-|-|
| `actor` / `action` | 操作人 / 动作（LOGIN/IMPORT/VALIDATE/REVIEW/PUSH/MODIFY/REJECT/…） |
| `entity_type` / `entity_id` | 对象类型 / 对象 ID |
| `detail` / `ip_address` | 操作详情 / 来源 IP |
| `row_hash` / `prev_hash` | 哈希链（本行 SHA256 含 prev_hash，链式串联、只追加） |

---

## 3. 溯源要求与验收

| 要求 | 说明 |
|-|-|
| **必留痕动作** | 导入 IMPORT、校验 VALIDATE、复核 REVIEW、推送 PUSH、驳回 REJECT、修改 MODIFY、登录 LOGIN |
| **只追加 + 防篡改** | 审计日志独立保留、只追加、哈希链可验证，满足合规审计证据 |
| **双向绑定强制** | `voucher_no ↔ record_id ↔ raw_id` 链不得断裂；推送成功必须回填凭证号 |
| **保留时长** | 建议 ≥ 5 年（财务合规确认，可上调） |
| **验收方式** | 溯源审计测试：抽样任意凭证/流水，全链路字段可回查，覆盖 100% |
