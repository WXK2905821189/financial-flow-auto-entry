## 0. 定位

本文档把「银行流水」到「金蝶云星空凭证」的财务记账口径落成可执行规则，覆盖三类：
1. **记账规则**：凭证类型、科目确定、借贷方向、摘要、币种；
2. **复核规则**：哪些自动通过、哪些转人工、复核动作与批量；
3. **核销规则**：收款冲应收、付款冲应付的一期收窄策略。

> 一期硬约束（范围守门）：**不做智能科目/往来匹配**（后置）。凡涉及「智能匹配」的部分，一期一律以「规则预置 + 人工复核兜底」替代，防止勾稽差异放大。

## 1. 记账规则

### 1.1 凭证类型判定

| `dc_flag` | 业务 | 金蝶单据 | 生成凭证 |
|-|-|-|-|
| `C`（贷方/流入） | 收款 | 收款单 | 收款凭证 |
| `D`（借方/流出） | 付款 | 付款单 | 付款凭证 |

### 1.2 科目确定

**（1）银行存款科目（自动，无需人工）**
- 系统按「银行 + 账号」映射到 **银行存款明细科目**（如 `银行存款-招商银行-尾号XXXX`）。
- 映射表由 `dim_bank_account` 关联维护，一期初始覆盖中信 & 招商全部账户，需在 UAT 前由财务确认科目表。
- 方向：收款→借方；付款→贷方（契约文档第 3 节）。

**（2）对方科目（一期策略，含人工参与）**

| 场景 | 一期处理 | 置信度 |
|-|-|-|
| 命中**预置映射规则**（摘要关键词 / 对方户名 → 科目） | 系统**预填**默认对方科目 | 高置信 → 自动通过 |
| 未命中规则，但有对方户名 | 挂默认往来科目（应收/应付或其他往来），**转人工**指定 `matched_subject` | 中置信 → 人工 |
| 无对方户名 / 字段异常 | 挂「待处理科目」，**强转人工** | 低置信 → 人工 |

**预置映射规则示例（种子，可配置）**：

| 触发条件（摘要/对方户名关键词） | 默认对方科目 |
|-|-|
| 银行手续费 / 手续费 | 财务费用-手续费 |
| 存款利息 / 利息 | 财务费用-利息收入 |
| 代发工资 / 工资 / 薪酬 | 应付职工薪酬 |
| 税费 / 税金 | 应交税费 |
| 客户回款（对方户名在应收主数据） | 应收账款 |
| 付供应商款（对方户名在应付主数据） | 应付账款 |

> 规则是可扩展字典（对应 `dim_validation_rule` 同类的科目映射表），一期只上少量高确定性规则，其余人工。

### 1.3 借贷方向与凭证分录

| 业务 | 凭证分录（一期固定骨架） |
|-|-|
| 收款（C） | 借：银行存款明细科目　贷：对方科目 |
| 付款（D） | 借：对方科目　贷：银行存款明细科目 |

金额 = 原币 `amount`（一期 = 本位币）。银行存款科目、对方科目、摘要如 §1.1–1.4。

### 1.4 摘要口径

- 凭证摘要 **默认取 `summary` 原文**；`summary` 缺失时拼接「对方户名 + 方向」生成默认摘要（如「收款-某公司」）。
- 不改写、不扩充原始摘要，保证与源流水逐字可对（溯源要求）。
- 金蝶摘要长度限制按 OpenAPI 截断（全栈确认，建议 512 内）。

### 1.5 币种与本位币

- 一期仅 `CNY`，原币 = 本位币，汇率 1；不涉及汇兑损益。
- 多币种、汇率、汇兑损益后置二期。

## 2. 复核规则

### 2.1 自动通过 vs 转人工

**自动通过（满足全部）**：
1. 校验 R001–R005 全部 PASS（无 FAIL、无 WARN）；
2. 对方科目已由预置规则命中（高置信）；
3. 金额 ≤ R004 阈值。

**转人工复核（满足任一）**：
1. 任一校验 FAIL / WARN；
2. 对方户名 / 摘要缺失（软必填缺失）；
3. 对方科目未命中预置规则；
4. 单笔金额超阈值（R004）；
5. 重复/负金额/币种非法（R001/R002/R005 FAIL → 需人工判定，驳回或修正后重采）。

### 2.2 校验规则与阈值（对齐 R001–R005）

| 规则 | 编码 | 级别 | 阈值 / 说明 |
|-|-|-|-|
| 重复流水 | R001 | ERROR | `dedup_key` 唯一索引冲突（同批/跨批重复导入） |
| 负金额/方向非法 | R002 | ERROR | `amount ≤ 0` 或 `dc_flag ∉ {D, C}` |
| 必填字段缺失 | R003 | ERROR | 硬必填字段缺失（`txn_date/txn_no/currency/amount/dc_flag`） |
| 软必填缺失 | R003b | WARN | `counterparty_name` / `summary` 缺失转人工 |
| 单笔金额超阈值 | R004 | WARN | 默认 单笔 > **50 万 CNY**（可配置） |
| 币种非法 | R005 | ERROR | 币种不在 ISO4217 合法取值 |

### 2.3 复核动作与批量

| 动作 | 含义 | 留痕 |
|-|-|-|
| `PASS` 通过 | 确认无误，可推送 | `biz_flow_review` |
| `REJECT` 驳回 | 退回（不推送），可修正后重采 | `biz_flow_review` |
| `ADJUST` 调整 | 改科目/金额/摘要后通过 | 记录 `matched_subject` + 变更 |

- **批量支持**：规则内（高置信）流水支持按批次/筛选**一键批量通过**，避免复核工时反噬；含 FAIL/WARN 流水须分组/逐条确认。
- 复核即出证的前提：对方科目已确定；未确定科目不得进入推送队列。

## 3. 核销规则（一期收窄）

> 核销 = 收款冲销应收、付款冲销应付。一期**不做**智能往来匹配，核销范围收窄如下：

| 项 | 一期口径 |
|-|-|
| 自动核销触发条件 | 仅当 **对方往来单位能唯一确定** 且 金蝶侧该单位**存在未结清应收/应付** 时，推送生成收/付款单后触发金蝶标准核销 |
| 不满足条件 | **不自动核销**，留月末人工核销 |
| 一期不支持 | 部分核销、多单位拆分、跨币种核销（二期） |
| 前置依赖 | 「对方户名 → 往来单位」主数据映射须在 UAT 前维护完成 |

> 核销动作由金蝶出纳/往来模块标准能力执行，中台只传递「对方往来单位 + 金额」，不自行生成核销分录（避免与金蝶口径冲突）。
