## 四、数据构成与逼真度

- **交易日期**：2026-08-24（周一，工作日）。
- **交易时间**：集中在 09:00–18:00，少量 18:00 后（平台结算/代发）。
- **收支结构**：收入（C 贷方）= 货款/服务费/项目回款/平台结算/咨询费；支出（D 借方）= 采购/广告/工资代发/劳务/房租水电/税费/报销/还款。
- **金额分布**：几百元（报销）到 30 万+（平台结算/工资代发），符合 200+ 人互联网公司日流水量级。
- **对方户名**：对公客户/供应商（公司名）+ 个人（报销），贴近真实。
- **流水号（招商）**：15 位字母数字（仿真实格式 `C0947BT0000CQ2Z`），全文件唯一；中信仍为 20 位数字。
- **交易类型（招商）**：网联付款申请收款 / 银联TOKEN贷记对公户入账 / 跨行转账支出 / 网上银行转账支出 / 代发工资 / 企业银行各项费用等，与摘要关键词强匹配。
- **摘要（招商）**：网联/银联结算用短码（`0824_1720219225`、`SA020008提现 2026-08-24`），手续费用费用名，其余保留业务摘要。
- **收付方开户行名（招商）**：按对方账号前缀推导（1109→工行北京、6222→建行北京、7559→招行深圳、8110→中信深圳等）。
- **扩展摘要/交易分析码/信息标志（招商）**：网联 AN 开头、银联 TK 开头，交易分析码 N6GATR/NPGATR/NEGATR，费用类信息标志=1。

## 六、使用方式

1. **Mock API 路径**：全栈适配器读取 `mock_cmb_flow_20260824.json` / `mock_citic_flow_20260824.json`，按批次元数据调用 `sp_ingest_flow` 落库。
2. **文件导入路径**：用 `mock_cmb_flow_20260824.csv` 走 FILE 适配器（`source_type=FILE`），验证 CSV→契约映射与落库。
3. **字段映射测试**：用 `mock_cmb_raw_20260824.json`（银行侧原始字段）验证适配层映射/清洗逻辑（千分位金额、中文借贷标志、日期格式、缺省币种）。
4. **校验测试**：用 `mock_anomaly_samples.json` 逐条验证 R001–R005 留痕与状态机（FAIL→LOADED / PASS→REVIEW_READY / WARN→REVIEW_READY）。
5. **切换验证**：先 Mock 后 File 导入同一批，验证链路不中断、`v_recon_balance` 差异为 0。

## 七、注意事项

- 本数据为**虚构测试数据**，公司名/户名/账号均为模拟，不涉及真实资金。

## 八、多日多账户版本（2026-08-24 ~ 08-28）

> 覆盖**连续 5 个工作日 × 招商/中信两账户**，用于模拟「按日增量采集」与多账户并行落库场景。

### 8.1 批次结构

多日版本 JSON 为**批次数组**，每个元素即一个「账户 × 日期」批次，可直接喂给 `sp_ingest_flow`：

```json
[
  {
    "batch_no":         "B20260824-CMB-1",
    "source_type":      "MOCK",
    "bank_id":          1,
    "account_id":       1,
    "source_ref":       "mock://cmb/2026-08-24",
    "contract_version": "v1",
    "flow_date_start":  "2026-08-24",
    "flow_date_end":    "2026-08-24",
    "imported_by":      "system",
    "flows": [ ... ]
  }
]
```

批次号规则：`B{YYYYMMDD}-{银行}-{日序号}`（CMB/CITIC 各 5 批，全局唯一）。

### 8.2 数据构成

| 维度 | 说明 |
|-|-|
| 日期 | 2026-08-24（周一）~ 08-28（周五），连续 5 个工作日 |
| 账户 | 招商（CMB，基本户）+ 中信（CITIC，一般户），每工作日两账户均有流水 |
| 笔数 | 每批次 11–16 笔，合计 **137 笔**（招商 66 / 中信 71），流水号全局唯一 |
| 收支 | 收入 6–8 笔/日（货款/服务费/项目回款/平台结算/软件开发费/广告服务费/咨询费/技术服务费/退款），支出 5–8 笔/日（采购/广告/劳务/云服务/电费/税费/物流/报销/办公用品） |
| 对手方 | **摘要类型与对手方强匹配**：电费→电力公司、工资代发→人力资源、劳务费→律所/人力、物流费→物流/快递、咨询费→咨询公司、差旅报销→个人等 |
| 周期性交易 | 工资代发 08-25（招商 28.5 万 / 中信 30 万，11:15:32）；房租 08-26 招商（12 万）；物业费 08-26 中信（3.5 万）；贷款还款 08-28 中信（15 万） |
| 流水号 | 招商 15 位字母数字（仿真实格式），**序号与交易时间严格递增一致**（排序后重分配）；中信 20 位数字 |

### 8.3 使用方式

1. **多日增量采集**：全栈按批次数组逐批调用 `sp_ingest_flow`（每批一个 `batch_no`），验证 10 个批次全部 `PASS → REVIEW_READY`。
2. **多账户并行**：招商/中信两文件可并行落库，验证 `v_recon_balance` 按批次/账户分别勾稽、差异为 0。
3. **文件导入（多日）**：用 `mock_cmb_flow_20260824_28.csv` / `mock_citic_flow_20260824_28.csv` 走 FILE 适配器，按 `txn_date` 切分批次或单批导入。
4. **周期性交易验证**：工资代发/房租/物业费/贷款还款固定日期时间，可验证「按日增量采集」下周期性交易的正确归批与去重（跨日重放不产生重复）。

### 8.4 异常/边界版本（`mock_*_flow_20260824_28_anomaly.json`）

> 在正常批次基础上注入异常流水，模拟**真实采集时批次混入脏数据**的场景。正常部分与正常版本完全一致（同 seed），异常流水独立流水号段（序号 9xxxxx 起）、时间取 18:00–23:00（日终）、带 `_test_case` 标注。

**注入清单（14 条规则异常 + 2 条边界 = 16 条）**

| 银行 | 日期 | 注入用例 | 预期 |

| 招商 | 08-25 | R004 超阈值（500 万） | WARN→REVIEW_READY |
| 招商 | 08-26 | R003 缺流水号、R005 币种非法 | FAIL→LOADED |

**预期批次汇总**

| 银行 | 批次 | 总笔数 | 正常 | 异常 | 预期 FAIL | 预期 WARN | 预期 PASS | 预期重复 |
|-|-|-|-|-|-|-|-|-|

**使用方式**：全栈/测试按批次调用 `sp_ingest_flow` 落库，逐条核对 `dwd_flow_validation` 留痕（rule_code/rule_result/error_detail）与 `process_status` 状态机；`v_recon_balance` 的 `count_diff` 应等于各批重复数、`amount_diff` 应反映 FAIL 笔金额。

### 9.2 真实数据特征（样本观察）

- **流水号**：15 位字母数字（如 `C0947BT0000CQ2Z`），非纯数字；第 7 位随日期变化（T→U→V→W 逐日递增）。
- **借贷列**：借方金额 / 贷方金额**分列**，一笔交易只填其一，另一列为空。
- **余额**：逐笔滚动余额（贷加借减），可校验连续性。
- **交易类型**：网联付款申请收款、银联TOKEN贷记对公户入账、企业银行各项费用等描述性类型。
- **摘要**：结算类为短码（`0101_1720219225`、`SA020008提现 2026-01-01`），费用类为费用名（`网银支付-跨行-异地手续费`）。
- **收付方**：收(付)方名称/账号/开户行名三件套；支付平台（财付通/支付宝）账号为 9 位短号。
- **交易时间**：含 05:xx / 11:00 / 23:00 等平台结算时点。
- **信息标志**：费用类交易 = `1`，其余为空。
- **扩展摘要 / 交易分析码**：AN/TK 开头扩展摘要 + N6GATR/NPGATR/NEGATR 分析码。

### 9.3 银行侧字段 → 统一流水契约映射

| 统一契约字段 | 招商网银导出字段 | 清洗/转换说明 |
|-|-|-|
| txn_no | 流水号 | 原样（15 位字母数字） |
| txn_date | 交易日 | 斜杠日期 `2026/08/24` → `2026-08-24` |
| txn_time | 交易时间 | 原样 HH:MM:SS |
| currency | 币种 | `人民币` → `CNY`；缺省补 `CNY` |
| amount | 借方金额 / 贷方金额 | 取非空列；千分位 `156,800.00` → `156800.00`；**恒正** |
| dc_flag | 借方金额/贷方金额 | 借方金额非空 → `D`；贷方金额非空 → `C` |
| counterparty_name | 收(付)方名称 | 原样 |
| counterparty_account | 收(付)方账号 | 原样 |
| summary | 摘要 / 用途 | 优先摘要，空则取用途 |

> 其余 27 列（起息日、交易类型、扩展摘要、交易分析码、信息标志等）作为**扩展字段**随原始流水归档 `ods_bank_raw_flow.raw_content`，不阻断标准字段落库。
