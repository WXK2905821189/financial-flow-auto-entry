# 财务流水自动入账系统 PRD

> 版本：一期 v1.0  
> 更新：2026-08-25  
> 状态：评审基线  
> 适用范围：一期 MVP（单主体、人民币、招商/中信优先）

## 1. 产品概述

财务流水自动入账系统面向财务人员，将银行流水统一采集、校验、复核并推送至金蝶云星空制证，形成从原始流水到会计凭证的完整可追溯链路。

系统一期采用“规则自动化 + 人工复核兜底”的方式：高确定性流水自动通过，存在缺失、异常、超阈值或科目未确定的流水进入复核队列。系统不以自动化替代财务判断，重点降低重复录入、漏记、错记和难以追溯的风险。

## 2. 背景与目标

### 2.1 业务问题

- 银行流水依赖人工下载、整理和录入，周期长且容易重复、遗漏或方向录错。
- 不同银行字段与借贷方向口径不一致，后续制证和对账容易产生差异。
- 异常流水、人工复核和金蝶凭证之间缺少稳定关联，审计回查成本高。
- 财务无法在一个工作台查看采集、复核、异常、推送与勾稽状态。

### 2.2 一期目标

1. 支持 Mock 银行、文件导入和银行 API 三种采集来源，统一转换为标准流水契约。
2. 在入库时完成去重、字段完整性、金额方向、币种和批次余额勾稽校验。
3. 按规则预填对方科目，让合格流水自动通过，其余进入人工复核。
4. 将已通过复核的流水推送至金蝶，记录凭证号、推送结果与重试信息。
5. 支持从凭证回查流水、从流水回查凭证，并为关键操作保留防篡改审计证据。
6. 提供复核工作台、异常预警、银行分布和对账钩稽等运营视图。

### 2.3 成功指标

| 指标 | 一期目标 |
|---|---|
| 流水可追溯率 | 100% 已入库流水可回查到原始来源和处理记录 |
| 重复入库 | 同一去重键不得重复生成主流水记录 |
| 自动化边界 | 仅校验通过且满足自动通过条件的流水自动流转 |
| 异常可见性 | FAIL/WARN 流水均可在看板或复核台定位原因 |
| 推送幂等性 | 同一流水重复请求不重复制证 |
| 回归基线 | 冒烟测试与 R003b、R006、银企 API 专项验证通过 |

## 3. 用户与角色

| 角色 | 核心诉求 | 主要操作 |
|---|---|---|
| 财务复核人员 | 快速确认低置信与异常流水 | 查看待办、指定科目、通过、驳回、批量处理 |
| 财务负责人 | 掌握处理进度和风险 | 查看看板、异常、对账、溯源记录 |
| 财务主数据维护人员 | 维护稳定的会计规则 | 提供银行存款科目映射和对方科目规则 |
| 系统管理员 | 管理访问与对接状态 | 登录、查看银行/金蝶/数据库状态，不在页面录入密钥 |
| 实施与运维人员 | 保证系统可用和可审计 | 部署、配置环境变量、执行回归、处理接口故障 |

一期采用简版账号与角色认证。多角色审批、细粒度权限和复杂组织隔离不在一期范围内。

## 4. 业务范围

### 4.1 一期包含

- 统一流水契约与版本管理。
- Mock、CSV、Excel、JSON 文件和银行 API 采集适配。
- 原始数据归档、批次管理、幂等去重和校验留痕。
- R001-R006 校验与余额勾稽。
- 规则型对方科目预填。
- 单笔、批量人工复核和复核审计。
- Mock 金蝶推送，以及真实 OpenAPI 对接切换入口。
- 凭证与流水双向溯源、审计哈希链。
- 复核工作台、四看板、系统对接状态页和 JWT 登录。

### 4.2 一期不包含

- 真实银行凭据申请、定时日切和生产银企直连运营。
- 智能语义科目匹配、多级审批流和完整 RBAC。
- 多主体、多币种、汇兑损益、复杂拆分和跨币种核销。
- 自动处理非唯一往来单位的核销。
- 在网页中编辑生产密钥或连接配置。

## 5. 核心业务流程

```text
登录
  -> 采集 Mock / 文件 / API 流水
  -> 归一化为统一契约并归档原始数据
  -> 去重与规则校验
  -> 规则预填对方科目
  -> 自动通过 或 转人工复核
  -> 推送金蝶生成凭证
  -> 凭证、流水、批次与审计记录双向溯源
```

### 5.1 流水状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| `LOADED` | 已入库；校验 FAIL 的流水也保留在此状态以留痕 | 修正后重采或人工处置 |
| `REVIEW_READY` | 校验 WARN 或需人工确认 | 财务复核 |
| `REVIEW_PASSED` | 已通过复核或满足自动通过条件 | 可推送金蝶 |
| `REJECTED` | 被人工驳回 | 不可推送，等待修正或重采 |
| `PUSHED` / `KINGDEE_POSTED` | 已发起或已完成金蝶制证 | 溯源、对账与异常监控 |

## 6. 功能需求

### FR-01 登录与访问控制

- 用户使用账号密码登录，系统签发 JWT。
- 未携带有效令牌访问业务接口时返回未授权。
- 首次启动可播种初始管理员；生产环境必须通过环境变量设置安全凭据。

验收：登录成功；业务接口无令牌访问被拒绝；设置接口不返回任何密钥明文。

### FR-02 数据采集与统一契约

- 支持 Mock、文件和 API 三类来源，输出同一个 `BankTransaction` 契约。
- 文件导入支持 CSV、Excel、JSON，支持列别名、借贷分列金额和脏行分类统计。
- API 采集支持健康检查、分页聚合、日期过滤、签名和清晰的账号/验签错误提示。
- 每次采集按银行和账号建立批次，记录来源、日期范围、预期笔数与金额。

核心字段：`txn_no`、`txn_date`、`txn_time`、`currency`、`amount`、`dc_flag`、`counterparty_name`、`counterparty_account`、`summary`。

验收：三种来源都能入库；脏行不静默丢弃；原始报文可回查；银行 API Mock 可完成分页全量拉取。

### FR-03 校验、去重与勾稽

| 规则 | 处理方式 |
|---|---|
| R001 重复流水 | 基于银行、账号、流水号、日期、金额、方向生成去重键；重复不新建主流水 |
| R002 金额/方向非法 | FAIL，保留留痕 |
| R003 硬必填缺失 | FAIL，保留留痕 |
| R003b 软必填缺失 | WARN，进入人工复核 |
| R004 单笔超 50 万 CNY | WARN，进入人工复核 |
| R005 币种非法 | FAIL，保留留痕 |
| R006 批次余额勾稽 | 有期初/期末余额时执行；不平衡标记异常 |

校验 FAIL 不直接标记为人工驳回；`REJECTED` 只表示财务人工驳回。

验收：同批与跨批重复均不重复入库；无对方户名流水进入复核；余额不平衡可见差异与规则结果。

### FR-04 科目预填与复核工作台

- 对摘要和对方户名按关键词/正则、方向、优先级匹配对方科目。
- 命中规则时，将预填结果写入扩展字段；未命中时由财务人工指定。
- 待办列表只展示 `REVIEW_READY` 流水，并提供流水详情、校验结果、原始信息和预填科目。
- 支持 `PASS`、`REJECT`、`ADJUST` 单笔与批量决策，记录复核人、时间、备注和人工指定科目。

验收：规则命中、未命中与方向过滤结果正确；复核后状态正确变化；每次决策均有审计记录。

### FR-05 金蝶推送与制证

- 仅允许已通过复核的流水推送。
- 收款流水（`C`）生成收款语义，付款流水（`D`）生成付款语义；银行存款科目方向按财务口径转换。
- 推送记录保存状态、凭证号、金蝶单据号、响应、错误信息和重试次数。
- `KINGDEE_MOCK_ENABLED` 控制 Mock 与真实 OpenAPI 切换；真实模式需具备已校准的凭据和字段映射。
- 同一流水重复推送应复用既有成功记录，不得重复制证。

验收：Mock 推送后返回凭证号；重复请求不产生第二张凭证；真实模式在金蝶测试账套完成创建、审核和回读验证。

### FR-06 溯源、审计与看板

- 支持按流水记录号和金蝶凭证号双向查询。
- 追溯链路必须覆盖批次、原始报文、校验、复核、推送和凭证。
- 关键动作追加写入审计日志，并通过前序哈希与本行哈希形成可验证链。
- 看板提供流水总览、银行分布、异常预警、批次对账和顶部统计卡。
- 系统设置页只读展示银行、金蝶、数据库和规则状态。

验收：任意成功凭证可回查原始流水；任意流水可查看推送结果；篡改审计日志可被哈希校验识别；看板端点可正确返回数据。

## 7. 关键业务口径

- 金额恒为正数；方向由 `dc_flag` 表示，`C` 为银行贷方/我方收款，`D` 为银行借方/我方付款。
- 收款凭证中银行存款记借方；付款凭证中银行存款记贷方。
- `txn_no` 只在“银行 + 账号”范围内唯一；全局幂等采用去重键。
- 一期仅支持 CNY，本位币与原币一致，汇率为 1。
- 对方科目一期仅做规则预填，未命中必须人工确认，不引入智能推断。
- 自动核销仅限唯一往来单位；其他情形保留月末人工核销。

## 8. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 密钥仅由环境变量或密钥服务注入；生产禁止默认密码和占位密钥 |
| 数据安全 | 原始流水与业务记录分层存储；审计日志只追加 |
| 可用性 | API 采集和金蝶调用支持超时、错误提示与有限重试 |
| 可维护性 | 业务域只能依赖 `core` 与 `models`；跨域常量上提至统一契约 |
| 部署 | 生产使用独立 VPC、MySQL 8.0 与网络访问控制；SQLite 仅用于演示/测试 |
| 可观测性 | 批次、规则、推送失败和对账差异必须在页面或日志中可定位 |

## 9. 上线验收

1. Mock、文件导入、银行 API Mock 三条采集链路全部通过。
2. 冒烟测试覆盖“登录 -> 采集 -> 复核 -> 推送 -> 溯源 -> 看板”并通过。
3. R003b、R006、API 适配专项验证通过。
4. 真实金蝶测试账套完成小批量制证、审核、回读和对账。
5. 生产环境不使用默认密钥、默认管理员密码或演示数据库。
6. 财务提供并确认招商/中信账户到银行存款明细科目的映射。
7. UAT 使用真实银行导出样本，完成导入、复核、推送和追溯抽样验收。
