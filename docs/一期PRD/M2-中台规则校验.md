# PRD · M2 中台规则校验

## 1. 目标
批次落地时执行流水校验与勾稽，保证进入复核前数据的完整性与可追溯性。

## 2. 范围
**含**：R001–R006 规则、批次级余额勾稽、去重幂等、校验结果留痕、统计回流。
**不含**：科目判定（M3）、复核审批（M4）。

## 3. 关键需求点
| 规则 | 语义 | 状态/口径 |
|---|---|---|
| R001 | 重复流水检测（dedup_key） | 已落地，主表幂等 |
| R002 | 必填/金额/方向非法 | 已落地（注：负金额/方向多数在适配层拦截） |
| R003 | 核心必填 | 已落地 |
| R003b | 对方账户名缺失 → **WARN** 不阻断（P3 决策） | **已落地 08-25** |
| R004 | 单笔 > 50 万 CNY → 转人工复核 | 阈值 500000，已在配置 |
| R005 | 其他业务校验 | 已落地 |
| R006 | 批次勾稽：期初+Σ收入−Σ支出≈期末（容差 0.01） | 已落地；无期初/期末则 SKIP |

关键口径：校验 FAIL 状态按 **LOADED**（先落库留痕），`REJECTED` 仅作人工驳回语义。

## 4. 验收 / 退出条件
- R003b：无户名账单进 `REVIEW_READY`（WARN）而非被拒（端到端用例 pass）。
- 校验 FAIL → LOADED；批次统计 failed/warned 正确回流。
- 同批重复 txn_no 只入主表一次；跨批重放不新增 record。

## 5. 依赖 / 卡点
- A3（适配层拦截 vs 校验层职责边界）属设计对齐，不阻塞。

## 6. 状态
已落地（R003b 与状态机已于 08-25 闭环，12 项专项用例全绿）。

## 7. 涉及
`services/validation.py`、`services/ingest.py`、`models/dwd.py`（batch/validation）；上游 M1，下游 M3/M4。
