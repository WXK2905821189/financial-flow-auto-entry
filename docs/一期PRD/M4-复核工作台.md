# PRD · M4 复核工作台

## 1. 目标
面向财务的 Web 复核台：对待复核流水人工决策（通过/驳回），配合 R004 超阈值自动转人工，形成 human-in-the-loop 闭环。

## 2. 范围
**含**
- 待复核队列（process_status=REVIEW_READY）
- 单笔复核（PASS/FAIL）与批量复核
- 复核状态机：REVIEW_READY → REVIEW_PASSED / REVIEW_REJECTED
- R004 超阈值（>50 万）自动进人工复核队列
- 复核列表透出 auto_subject 等关键字段

**不含**：多级审批流、复核权限角色矩阵（二期）。

## 3. 关键需求点
1. 待办队列取 `REVIEW_READY`；规则 MISS/FAIL/WARN 分流明确。
2. 单笔/批量复核都写审计留痕；复核结果驱动 M3 推送。
3. 看板口径与复核状态解耦（via `v_*` 视图）。

## 4. 验收 / 退出条件
- 单笔复核→推送→溯源链路通（smoke 覆盖）。
- R004 超阈值单进入待办而非自动通过。
- 复核操作可追溯（谁/何时/结果）。

## 5. 依赖
- 上游 M2 校验结果、R004 阈值配置（500000）。

## 6. 状态
已落地（前端 review.js + 后端 api/review.py）。R004 阈值已按 50 万校准。

## 7. 涉及
`api/review.py`、`services/review.py`、`models/biz.py`、`web/js/review.js`。
