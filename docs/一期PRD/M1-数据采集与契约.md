# PRD · M1 数据采集与契约

## 1. 目标
接收多家银行流水，归一化为统一契约 `BankTransaction`，进入数据中台。支持可插拔数据源：模拟银行、文件导入、真实 HTTP 银企。

## 2. 范围
**含**
- 统一流水契约：`BankTransaction`（恒正金额 + `dc_flag` 方向、8 核心字段 + `ext` 扩展留痕）
- 适配器注册表 + 三类适配器（Mock / File / API）
- 字段差异（多银行命名/借贷/币种）清洗归一
- `/api/ingest/mock|file|api` 三个入库端点
- API 路联调内网银企（翻页聚合、MD5 验签、健康检查）

**不含**：真实银行银企直连凭据申请（D3，一期未决、二期联调）；定时日切采集（二期）。

## 3. 关键需求点
1. 三源输出同一 `BankTransaction` schema。
2. 文件导入支持 CSV/Excel/JSON，列别名映射、借/贷分列金额回退、中文清洗；脏行跳过并归类返回。
3. API 路自动翻页聚合（≤200/页），验签失败/账号错误须明确报错。
4. `source_ref` 带上采集水位线（为二期增量留钩），入库 `source_type` 留痕切换。

## 4. 验收 / 退出条件
- 三适配器产物通过契约测试。
- API 联调：招商 66 / 中信 71 全量拉取成功、字段正确映射、错误账号报错。
- 文件导入脏行返回 `skipped:{total,reasons}`，不静默吞。
- `smoke_test.py` 无回归。

## 5. 依赖 / 卡点
- 真实银企凭据（D3）→ owner/截止日缺失（外部待办）。
