# PRD · M3 科目预填与凭证生成

## 1. 目标
按财务规则自动预填对方科目（决策 P1），并对已复核流水推送给金蝶生成记账凭证。

## 2. 范围
**含**
- 科目规则预填：`account_mapper.py`（关键词/正则、方向过滤、优先级升序、首条命中）
- 维度表 `dim_account_mapping` 维护科目映射规则
- 预填结果写 `ext_json.auto_subject`
- 金蝶推送：mock 推送（凭据未就绪）→ 真实 OpenAPI 对接（BatchSave 制证）
- 推送幂等（record↔voucher 双向绑定），push 记录留痕

**不含**：真实金蝶 OpenAPI 凭据（前置卡点）；科目"全自动硬控"（一期走复核后推送）；智能科目语义解析。

## 3. 关键需求点
1. 规则命中即自动预填对方科目到 `ext_json.auto_subject`；未命中留空由人工指定。
2. 科目规则可维护（财务 UAT 前提供生产规则表，对应 P4）。
3. 推送前后置/幂等/审计留痕；`KINGDEE_MOCK_ENABLED` 开关控制 Mock↔真实切换。
4. 真实对接：官方 Python SDK 或自实现 HMAC-SHA256（见《金蝶真实对接落地要点.md》）；制证端点 BatchSave；报文以官方在线测试+接口说明书校准。

## 4. 验收 / 退出条件
- 预填命中/未命中/方向过滤用例通过（verify_r006_mapping 覆盖）。
- Mock 推送 + 自动制证链路通；真实 Block 切真实后金蝶可创建→审核→对账一致。

## 5. 依赖 / 卡点（关键挂起）
- **金蝶 OpenAPI 凭据**（owner/截止日缺失）——09-16 链路打通的硬前提。
- 财务 P4「银行存款科目映射表」用于生产规则。

## 6. 状态
预填已落地；金蝶真实推送**进行中（Mock）**，凭据就绪即切真实。

## 7. 涉及
`services/account_mapper.py`、`services/kingdee.py`、`services/push.py`、`models/dim.py`；上游 M2，下游受 M4 审批驱动。
